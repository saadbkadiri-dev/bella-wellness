# Bella Wellness Project Context

## Overview
Bella Wellness is an exclusive sanctuary designed entirely for women to move, heal, and glow. It is built as a highly responsive, modern, minimalist Next.js web application.

## Tech Stack
- Framework: Next.js 15 (App Router)
- React: 19
- Styling: Tailwind CSS v4 (using `@theme` in `globals.css`)
- Typography: Montserrat site-wide (all headings and body text) via `next/font/google`, weights 300–700. Libre Caslon Display and Sora have been removed — the editorial serif/sans contrast is gone in favor of a single typeface differentiated by weight.
- Animations: Framer Motion (for staggered reveals, asymmetric transitions, and hero slide carousel)
- Smooth Scrolling: Lenis

## Design System & Rules
- **Aesthetic:** Editorial, organic, tactile, high-end luxury.
- **Layout:** Asymmetric split layouts (e.g., 55% text, 45% image), fluid overlapping, left-aligned text preference.
- **Hero Headline Case:** Displayed uppercase via CSS `text-transform` (Tailwind `uppercase` class), `font-light` weight. "For Women." is joined with a non-breaking space so it never breaks across lines; "Sanctuary" can still wrap onto its own line.
- **Kicker/Eyebrow Labels:** Small uppercase section labels (e.g. "OUR SANCTUARY • BEIRUT") are `13px`/`font-semibold` sitewide (bumped up from `11px`/`font-medium`).
- **Fluid Type Tiers:** `.text-fluid-hero` (hero h1), `.text-fluid-h2` (large section headings — About, Why Bella Wellness), `.text-fluid-h3` (smaller section headings — Intro Strip, Services), `.text-fluid-body`.
- **Avoid:** Generic blocks, cards with heavy drop shadows, rounded pills, horizontal dividers, and centered AI-looking templates.
- **Phase 1 Rules:** Zero CTAs or buttons. No external booking links yet. Note: the hero headline now reads "SANCTUARY FOR WOMEN." per explicit user request, diverging from `content.md`'s canonical tagline ("A community of women thriving in wellness."); `content.md` itself has not been updated to match, and the Footer no longer displays that tagline quote at all (it was removed).
- **Long Hyphens:** Em dashes (—) have been removed from all site copy (hero, About page body text, `content.md` source) in favor of plain short hyphens ( - ), per explicit user request. Not yet codified as a standing rule — confirm with user before treating as permanent.
- **Deploy Rule:** Do NOT deploy to Vercel without explicit user permission.

## Current State

It's one bordered/textured outer container (`#F9F7F4`, texture lives on the page background behind it, not on the container itself) holding four individually-boxed categories (Location, Reach Us, Hours, Connect — each its own `border border-black/10 bg-[#F6F3EF]` card) stacked on the left, paired with a real photo (`bella-wellness-cam5.webp`, reused from Gallery) on the right. On mobile the 4 category cards share a uniform `min-h-[260px]` (content length varies a lot per card, e.g. Location's paragraph vs. Connect's single link, so without a shared min-height they visibly don't match) and sit fully inset within the outer container's padding — no bleed on mobile. On desktop (`lg:`) the category-card column bleeds to the outer container's left edge (`lg:-ml-12`, min-height reset off) and the photo bleeds to the top/right/bottom edges (`-mt/-mr/-mb` matching the container's own padding, combined with a `calc(100% + padding*2)` height since negative margin alone shifts a fixed-height box rather than growing it — a plain `-mt`+`-mb` pair only moves the box, it doesn't add height on both sides at once). Photo is desktop-only (`hidden lg:block`), sharp corners, no border. The arch image crossfade used `AnimatePresence mode="wait"`, which fully unmounts the old image before the new one mounts — since the clip-path container has no fill of its own, that gap made the whole arch flash invisible on every service switch. Fixed by dropping `mode="wait"` (images now crossfade with overlap) plus a `#0C0D0D` background-color fallback on the container as a second safety net.

- **Recurring gotcha, hit twice this session:** the local Next.js dev server's `.next` build cache can go stale mid-session (JS chunks 404 / a component visually doesn't reflect its actual source code, even though the source is correct and `tsc` is clean). Fix: `lsof -ti:3000 -sTCP:LISTEN | xargs -r kill && rm -rf .next && npm run dev`, then hard-refresh the browser. Worth checking this *before* assuming a rendering bug is a real code issue when the DOM/computed-style evidence contradicts what's visually reported.
